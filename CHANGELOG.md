# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The site documents Claude Code `2.1.316`, the only release it tracks. The version of the site itself is set in `package.json`, and the tracked Claude Code version is set in `src/version.ts`.

## [Unreleased]

### Added

- A second plugin, `cc-inspect`, with an MCP server and a skill that read your session transcripts (list, read, search, and check each line against the transcript schema) and the installed Claude Code binary (installs, modules, search, read, and the keys of an object literal or an OpenTelemetry event).
- `cc-inspect` 0.3.0: a `list_surface` tool that lists the items of one kind in the installed binary (environment variables, flags, subcommands, slash commands, settings, hook events, gates, tools, OpenTelemetry events, Mod API calls and events, keybindings, models, betas, endpoints, files, permission modes, and error texts), with a name filter and paging. Without a kind, it gives the count of each kind. Error texts from bundled CommonJS library modules are left out. Those from ES-module libraries are still listed.
- A surface snapshot of the program (`schemas/surface.json`, made by `bun run surface`) that `schemas:check` compares with a fresh run, and a `surface:check` script that lists the items no page maps yet. A generated Surface Coverage page lists every item with its page, and the Undocumented Items page shows the count of each kind.
- The exact fields of every payload, made from the program: the Mod API type file (`schemas/claude-code.d.ts`) and 11 more JSON Schemas (hook output, built-in tools, control protocol, stream-json, `--agents` JSON, `.mcp.json`, frontmatter, status line input, transcript lines, OpenTelemetry, `~/.claude.json`). The MCP server's `get_schema` serves them all, and looks up types, `$` calls, and events in the type file.
- A rule for agents in the skill and the docs: look a field up in these files before stating it, and name only the fields found there.
- A Context Budget page with live `/context` measurements: an empty session, the first turn, the cost of each tool, and best practices.
- An Override a Prompt page, and captures of about 30 more prompts (built-in agents, commands, bundled skills, hooks, the auto mode classifier, compaction).
- Overview pages for each top-level section, so breadcrumbs link back.
- Prompt pages that show what you can override and its default text: Tool Descriptions (every tool's description and input schema), Built-In Agents, and Built-In Skills.
- Status labels (Managed Only, Experimental, Deprecated, Caution) in place of emoji markers, and screen-reader text for ✅ and ❌.
- A `check:examples` gate that runs Biome on code examples, and `check-docs` rules for code spans in headings and admonition titles.
- An unofficial docs site for Claude Code `2.1.311`, with pages for start, configure, extend, prompts, reference, and how it works.
- Provenance badges (Documented, Undocumented, Differs, and Gated) that mark each item.
- A style guide for contributors in `docs/contributing/`.
- Capture and check tools in `tools/`, and a GitHub Pages deploy workflow.
- A third plugin, `cc-docs-cli` 1.0.0: a `cc-docs` command (`search`, `read`, `list`, `schema`, with `--source`, `--section`, `--limit`, and `--json`) that the Bash tool runs, plus a skill. It has no MCP server, so it adds no tool list to the context. It shares its code with the `cc-docs` server.
- `cc-inspect` 0.4.0 reads a release from its code: `code` `prepare` cleans each module of a version (stable local names) into a cache, `release` `diff` lists the functions changed, added, and gone between two versions, `release` `notes` marks each release-notes line as matched, gated, or unmatched against that diff, `release` `explain` gives where a name's code is, who uses it, what guards it, and whether it is a no-op, a stub, or handled, and `code` `find` finds code by plain words. Two MCP prompts, `release_review` and `explain_change`, give an agent the steps. `release:all` runs the new `release:clean` step.
- An Account and Access page: where Claude Code gets your plan, the profile request, where the login and account record are kept, when it asks again, and how the plan and the provider decide which models `/model` lists, including Fable and Mythos.
- The site build writes `llms-search-index.json`, a prebuilt search index of every page. `cc-docs` and `cc-docs-cli` load it in one request in place of fetching each page.
- `cc-inspect` 0.6.0: `code` `run` runs a prompt or slash command with `claude -p` against a local fake API (a fake key, a dead proxy, temp folders it removes) and gives the user turn the program sends, such as the text of a bundled skill that the binary does not hold as plain text.
- `clawdipedia-docs` 2.0.0 reads four sources with one tool set: `clawdipedia` (this site), `code` (<https://code.claude.com/docs>), `platform` (<https://platform.claude.com/docs>), and `anthropic` (<https://www.anthropic.com> news, research, and legal pages). `search_docs`, `read_page`, and `list_pages` take a `source`. `code` and `platform` read `llms.txt` and the `.md` form of a page. `anthropic` reads the sitemap and converts the HTML with `node-html-parser` and `node-html-markdown`, and `@rgrove/parse-xml` reads the sitemap. `get_schema` still reads this site only.
- A Capabilities of the `init` Line section on the Stream JSON Messages page: all 24 capability strings the program can put in `capabilities` of a `system` / `init` line, each with what makes it appear and what it means. The array tells a host which protocol features this CLI has, so the host can check a feature in place of a version. `ask_user_question_unanswered_v1` is new in `2.1.312`. The `AskUserQuestion` row of the Tools reference now names `annotations[question].unanswered` and its three values, `skipped`, `replied_in_chat`, and `dismissed`.
- `cc-inspect` 0.8.0: `sessions` `action: "tool-calls"` counts the real `tool_use` blocks per tool name across your transcripts, with a substring or regular-expression `query`, samples, and the usual `session`, `project`, and `limit` filters. It reads the subagent transcripts too, which the other actions skip.
- Evaluation cases for both MCP servers, written from real use: `plugin/mcp/evaluation.xml` grows from 16 to 39 pairs and now covers each tool, each `source` value, `read_page` with `section_heading` and with `offset` and `max_chars`, `search_docs` with `limit`, `list_pages` with `section`, and `get_schema` with `name` and `property`. A new `inspect/mcp/evaluation.xml` holds 16 pairs for `code`, `surface`, `sessions`, and `release`. A test in each package checks that the pairs cover the tools and that every route and argument exists.
- `cc-inspect` 0.7.0: `code` `run` takes `env`, extra environment variables for the run (it refuses the names it sets itself, and names or values that could carry a credential or send a request past the fake API, such as a proxy, a base URL, or `NODE_OPTIONS`). A run that times out now reports the stream-json events and the stderr from before the hang.

- **Breaking:** the release tool no longer calls a version-labelled sentence a "claim". It is a "fact". The program itself uses "claim" for a JSON Web Token claim, such as `email_claim`, `additionalClaims`, and the work-order claims that the Remote and Cloud Sessions page documents, so one word meant two things. `fact` is an approved noun in the ASD-STE100 Issue 9 dictionary, with the meaning "Something that occurred or is correct". The folder `tools/release/claims/` is now `tools/release/facts/`, the script `release:claims` is now `release:facts`, the output `captures/<version>/claims.json` is now `facts.json`, and the `claims` array of a probe result is now `facts`. The keys of `tools/release/facts/map.json` are unchanged, because they hash the page content and not the tool. There is no alias for the old names.
- **Breaking:** the value a probe observed was the type `Fact` with the field `facts`. It is now the type `Data` with the field `data`, which frees the word `fact` for the sentence on the page. `data` is also an approved ASD-STE100 noun, with the meaning "Numbers and symbols used by computers". The program's own type file uses "fact" for a pinned rendered value, so the two words now match their sources. Every capture under `captures/` must be rebuilt, because the field name in each result file changed.

Every absolute URL the site publishes changed, so each JSON Schema `$id` moved from `https://xsyetopz.github.io/clawdipedia/schemas/<name>.json` to `https://clawdipedia.cc/schemas/<name>.json`. A `$schema` line that names an old address no longer resolves, so edit it. The old addresses are not served. `baseUrl` is now `/`, so every page URL loses the `/clawdipedia` prefix.

Wrangler turns each one on when the config leaves it out. `wrangler` 4.154.0 is a pinned devDependency, so every deploy command uses `bunx`. A new `deploy:check` script runs `wrangler deploy --dry-run`, which validates the config against `build/` and deploys nothing. `verify` runs it last, after the build.
